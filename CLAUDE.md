# MetaCity – hierarchical traffic digital twin (static web MVP)

A browser-only traffic twin at four levels: Germany (motorway statistics) > Aachen (hourly
macroscopic model) > corridor (vehicle simulation) > junction (sensor-mast view). Each level
answers rule-based questions for its user (federal planner, municipal planner, driver).
There is no backend. An optional "Ask Claude" mode uses the viewer's own API key. Sibling of ../MetaHospital and ../MetaAgri, same conventions.

## Repo layout
- web/                 the whole MVP (static site, no build step)
  - index.html         page shell; loads d3 from cdnjs, then src/main.js
  - src/main.js        router (hash tokens), top bar, shared clock, render loop
  - src/engine/        the twin; twin.js is the facade and owns the hand-overs between levels
    - country.js       level 1: AADT statistics -> hourly load, CO2, what-ifs
    - city.js          level 2: gravity demand + MSA/BPR assignment per hour, scenarios
    - corridor.js      levels 3-4: IDM vehicles, signals, sensor masts, loop counters
    - perception.js    what the twin knows: mast event classifiers (prompt-defined classes) and
                       connected-vehicle hazard reports -> alerts; incidents are simulation truth
    - ask.js           question catalogue per level, answers, free-text matching
  - src/llm/claude.js   optional Claude layer: question catalogue as tools, manual tool loop,
                       raw fetch to the Messages API (no SDK: no bundler), injectable fetch for tests
  - src/ui/            views: country.js, city.js, corridor.js (canvas), street3d.js (three.js junction,
                       loaded on demand), ask.js (panel), dom.js
  - src/data/          germany-roads.js, aachen.js (schematic network of real streets, official 2024 population per zone), germany.js (states)
    - real/            generated by tools/build-data.mjs: motorways.js (BASt: per segment + every station),
                       aachen-osm.js (OSM lanes/speed limits), SOURCES.md (sources and terms)
  - styles/            base.css (tokens + shared components), views.css
  - test/              node:test suite for the engine
  - tools/             serve.mjs (port 8090), build-data.mjs, make-artifact.mjs

## Rules
- Vanilla ES modules only, no bundler, no npm runtime dependencies. d3 (always) and three.js r128
  (only when the 3D view opens) are the only libraries, both UMD globals from cdnjs.
- The engine never touches the DOM, Math.random or Date. Randomness goes through the Twin's
  seeded rng; read-only queries (questions, sensor views) must not advance it (use hashFloat).
- Views read through Twin methods and change it only via tick(), setTime(), setScenario(),
  resetScenario(), addIncident(), clearIncidents(), setMastHealth(), reviewAlert() and reset().
- Answers about events use perceived alerts, never simulation truth (label any truth as a check).
- Every answer states its level, data basis, resolution and confidence.
- Claude only reads the twin through its question tools; it never changes the twin (Apply stays a
  human button). The API key stays in the browser (localStorage only if the viewer opts in) and
  goes only to api.anthropic.com. Model claude-opus-5-5, effort low, fallbacks "default".
- Build markup with the `html` tagged template from dom.js; colours only through base.css tokens.
- Routes are plain hash tokens (`#germany`, `#aachen`, `#julicher`, `#julicher.j2`).
- Every number shows whether it is measured (BASt), real (OSM), illustrative or simulated; sensor
  masts are fictional. BASt stations are shown with their latest count and attribution (the
  owner decided this on 2026-10-13; BASt states no licence); keep BASt and OSM credited in the footer.
- `main` deploys to the live site on every push: develop on a branch, merge when tests pass and
  the change is checked in the browser.

## Commands (from web/)
- `npm test`, `npm run data` (refresh BASt + OSM; keeps committed modules on failure),
  `npm run serve`, `npm run artifact`

## Working style
- Small steps, ask before large refactors. Prefer simple code over clever code.
